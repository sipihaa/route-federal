# Route Federal

Курсовая по разработке мобильных приложений на Kotlin: Android 10+, Jetpack Compose. Задание — `route_federal.pdf`. Актуальное состояние — 16 сентября 2026 года.

Приложение ищет три маршрута по локальному реальному расписанию Яндекса. Выбираются **города**: все загруженные станции каждого города участвуют в общем поиске. Пересадки возможны только на одной физической станции. Дата — начало окна отправлений (по умолчанию восемь дней), а длительность считается от первой посадки с ожиданиями пересадок. Дата отправления видна в результате.

В наборе за 21–28 сентября: **1787 датированных рейсов, 18 станций, шесть городов** — Москва, Орехово-Зуево, Петушки, Владимир, Суздаль, Нижний Новгород. Поезда, электрички и автобусы; авиации и внутригородских участков нет. JSON — около 1 МБ. Офлайн-карта содержит границы и русские названия регионов; кнопки «Россия» и «Города» меняют обзор.

## Запуск

SDK и ARM64-эмулятор подготовлены в локальных каталогах проекта. Из терминала IntelliJ IDEA:

```sh
source tools/android-env.sh
./gradlew :app:assembleDebug
emulator -avd RouteFederal_API29 -gpu host -no-snapshot
```

В другом терминале:

```sh
source tools/android-env.sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n ru.milin.routefederal/.MainActivity
```

Основной APK содержит карту, но не ключ и временное расписание. Файл `.yandex-cache/timetable.json` нужно перенести на устройство и открыть в «Данные → Импортировать расписание». На рабочем эмуляторе база уже установлена. Пример поиска: Москва → Нижний Новгород, начало 21.09.2026, окно восемь дней. В этой версии набора три лучших длительности — 228, 230 и 234 минуты.

## Обновление данных

На Mac: `python3 tools/download_yandex_network.py --download`, затем `python3 tools/prepare_yandex_timetable.py`; после этого импорт нового файла в приложении. Прямой сетевой загрузчик в Android пока не реализован. [Настройка ключа и квоты](docs/YANDEX_SETUP.md), [сеть и пропуски](docs/YANDEX_NETWORK.md).

Кэш текущего набора действует до **21 сентября 2026, 19:57 по Москве**. Это срок хранения, а не конец периода поездок. Повторный импорт не продлевает срок. Перед более поздней демонстрацией нужен свежий набор. Исходная загрузка потребовала 214 новых запросов, с прежними попытками — 243 за 24 часа при пределе проекта 250. Для доработки городов и карты новых запросов к Яндексу не выполнялось.

## Проверки

```sh
source tools/android-env.sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebugAndroidTest
./gradlew :app:connectedDebugAndroidTest
python3 -m unittest discover -s tools -p 'test_yandex_*.py'
```

Для теста реальной сети положить свежий нормализованный файл в `.yandex-cache/android-test-assets/yandex_timetable.json` до сборки тестового APK. Он не попадает в основной APK или Git. Искусственные данные находятся только в тестах. [Протокол текущего этапа](docs/validation/cities-2026-09-16/README.md), [предыдущая интеграция](docs/validation/yandex-2026-09-15/README.md).

## Документация и ограничения

[План](docs/PLAN.md), [формат данных](docs/DATA_FORMAT.md), [настройка среды](docs/SETUP.md). ТЗ и отчёт — DOCX в корне; актуальные изменения приведены в приложении Ж. Основной текст и приложения А–Е пока сохраняют явно обозначенный предыдущий этап и требуют итоговой синхронизации листингов и UML.

Поиск охватывает только загруженные связи, а не полные сети четырёх регионов. В частности, API не вернул автобусы Владимир → Нижний Новгород за выбранные даты. Отсутствие результата не означает отсутствия сообщения. Наличие билетов не проверяется. Запас пересадки при неизвестном правиле станции — изменяемый параметр, по умолчанию 30 минут. Импорт ограничен 20 МБ; национальная производительность не заявляется.
